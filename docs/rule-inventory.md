# Narrow C++ enforcement inventory

Coverage inventory for the complete draft 0.1, sequence 11, audited 15 October 2026. The combined profile fails diagnosed bans and warns on restricted uses. Routes and evidence describe implemented subsets, not compliance percentages or whole-program safety.

Source: [Narrow C++](../policy/narrow-cpp.md), draft 0.1, sequence 11. Exact source block IDs are stored in [rules.json](../policy/rules.json).

All 57 blocks have a disposition: 41 substantive blocks map to 85 grouped items; 16 metadata, heading, status, or example blocks are recorded as context in the JSON.

`syntax` checks a concrete form; `review-sites` flags a use whose qualifying purpose needs human judgment; `mixed` combines these; `none` has no direct enforcement. `fixture-tested` verifies only the linked examples, not every named API or semantic clause. `implementation-only` has no dedicated fixture for this item. `not-configured`, `not-implemented`, `partial-toolchain`, and `review-required` identify remaining work.

Routes: `custom-partial` is an implemented subset, `upstream-partial` is upstream assistance, `custom-candidate` is proposed work, `build` belongs partly to toolchain integration, and `review` requires design judgment. Check annotations distinguish fixture evidence, enabled checks without item-specific evidence, and disabled candidates. Task callback model configuration is separate from enabling exception-escape.

The combined profile promotes 19 ban checks to errors. Other enabled checks remain warnings. Severity is shown beside each check; local suppressions still require a valid policy reason. A consuming build must run clang-tidy as a required step.
